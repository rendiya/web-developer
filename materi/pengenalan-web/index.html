Apa itu World Wide Web?

World Wide Web (WWW) adalah sistem informasi di internet yang memungkinkan dokumen dan sumber daya terhubung satu sama lain melalui hyperlink dan dapat diakses melalui browser.

Internet vs World Wide Web

💡 Internet = Jalan Raya  |  World Wide Web = Kendaraan yang berjalan di atasnya

🌐 INTERNET

Infrastruktur global jaringan komputer.

  • Jaringan fisik: kabel, router, server
  • Protokol TCP/IP
  • Mencakup: Email, FTP, VoIP, Web

🕸️ WORLD WIDE WEB

Layanan yang berjalan di atas internet.

  • Dokumen HTML / Website
  • Protokol HTTP/HTTPS
  • Menggunakan Browser sebagai klien

BAGIAN 6

Arsitektur Web: Monolith vs Microservices

🏗️

Arsitektur Aplikasi

Arsitektur aplikasi adalah cara sebuah sistem software dirancang — berdampak besar pada skalabilitas, kemudahan maintenance, dan performa jangka panjang.

🧱

Monolithic

Satu aplikasi besar. Semua modul menyatu dalam satu unit deployment tunggal.

🔬

Microservices

Banyak layanan kecil yang independen, masing-masing dengan tanggung jawabnya sendiri.

🧱

Monolithic Architecture

Semua komponen aplikasi tergabung dalam satu codebase dan di-deploy bersama.

  • Satu repository Git & Satu database
  • Di-deploy sebagai satu kesatuan
  • Komunikasi modul sangat cepat (in-memory)
  • Sangat ideal untuk startup / fase awal
🌐 HTTP Request
➜

🖥️Frontend
⚙️Business Logic
🔐Auth
💳Payment
🗄️ SINGLE DATABASE
🧱

Pros & Cons: Monolith

✅ Kelebihan
✓ Sederhana untuk di-develop & test
✓ Deployment mudah (1 server)
✓ Komunikasi antar fungsi sangat cepat
✓ Biaya server di awal lebih murah
❌ Kekurangan
✗ Semakin besar = kode makin rumit/lambat
✗ Bug fatal di 1 modul bisa mematikan seluruh aplikasi
✗ Sulit scaling untuk bagian tertentu saja
✗ Teknologi stack terkunci, sulit update teknologi
🔬

Microservices Architecture

Aplikasi dipecah menjadi layanan-layanan kecil yang berkomunikasi via API atau Message Queue.

  • Setiap service punya database sendiri
  • Deploy secara independen
  • Bisa beda bahasa pemrograman (Polyglot)
  • Infrastruktur jauh lebih kompleks

Pros & Cons: Microservices

✅ Kelebihan
✓ Bisa men-scale hanya bagian yang ramai
✓ Kegagalan satu service tidak mematikan semua
✓ Tim besar bisa bekerja secara terpisah & paralel
✓ Bebas memilih bahasa/tech terbaik untuk tiap service
❌ Kekurangan
✗ Kompleksitas infrastruktur sangat tinggi
✗ Debugging error jauh lebih sulit (tracing)
✗ Masalah konsistensi data antar database
✗ Biaya operasional server/cloud melonjak tinggi
⚖️

Perbandingan Lengkap

📊 Aspek🧱 Monolith🔬 Microservices
CodebaseSatu repository tunggalBanyak repository terpisah
DatabaseSatu database terpusatDatabase per service
DeploymentDeploy satu unit bersamaDeploy per service mandiri
SkalabilitasHarus scale seluruh aplikasiScale per service spesifik
KomunikasiIn-process (sangat cepat)Via API/Network (ada latency)
Kompleksitas AwalRendahTinggi
🤔

Kapan Menggunakannya?

💡 Saran: Mulai dengan Monolith yang rapi (Modular Monolith). Jangan terburu-buru migrasi ke Microservices jika sistem belum kompleks!

🧱 Pilih Monolith jika...

  • Startup fase awal (MVP)
  • Tim kecil (< 10 dev)
  • Domain bisnis masih sederhana
  • Ingin pivot fitur dengan sangat cepat

🔬 Pilih Microservices jika...

  • Aplikasi sudah berskala enterprise besar
  • Tim engineering besar (30+ dev)
  • Beberapa bagian butuh skalabilitas masif
  • Ada dana & engineer DevOps yang mumpuni
🌍

Contoh Nyata di Dunia

Skalabilitas bukan hanya soal microservices, tapi arsitektur yang dirancang dengan baik sesuai kebutuhan. Bahkan Stack Overflow bertahan di Monolith!
